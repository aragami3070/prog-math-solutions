# Оценка поиска (offline)

Протокол: `.agent/rust-knowledge/evaluation.md`. Инструмент: `cargo run --bin eval -- <команда>`
(читает БД и индекс, к сайтам-источникам не обращается).

| Файл | Что это |
|---|---|
| `queries.jsonl` | 84 запроса: `query_id`, текст, `intent`, язык, фильтры, `split` (dev/test), `group` (перефразы одной потребности попадают в один split) |
| `runs/<вариант>.tsv` + `.meta.json` | выдача варианта (top-20) и его паспорт: поколение индекса, версия анализатора, sha256 корпуса и запросов |
| `pool.jsonl` | кандидаты для разметки: объединение top-20 вариантов и выдач перефразов, перемешаны, без рангов и оценок |
| `labels.txt` | исходные оценки: `query_id документ=оценка …`; `@qNNN` включает оценки другого запроса той же потребности; непомеченный кандидат пула = 0 |
| `judgments.jsonl` | все суждения с исполнителем, основанием и свидетельством (собирается из `labels.txt` и пула) |
| `qrels.tsv` | итог: `query_id`, `document_id`, `grade` (0/1/2), читает `eval score` |
| `reports/<вариант>.{json,md}` | метрики по срезам |
| `review/` | слепая выборка для человека и `human.tsv` для его оценок |

## Шкала
2 — документ по существу отвечает на потребность (для `rfc_id` — именно этот RFC); 1 — по теме, полезный контекст;
0 — нет. Неоценённое (`unjudged`) не равно 0: см. «покрытие оценками@10» в отчёте. Для запросов с фильтром
документы вне фильтра получают 0 (их выдача не может вернуть).

## Порядок работы
```bash
eval rebuild                                  # индекс из БД
eval run --variant b0                         # выдача + паспорт
eval pool --runs eval/runs/b0.tsv,eval/runs/group-peers.tsv
# разметить новых кандидатов (labels.txt -> judgments.jsonl -> qrels.tsv), затем:
eval qrels && eval score --variant b0
eval compare --a b0 --b <вариант>             # paired bootstrap по группам запросов
```
После каждого нового варианта (typo, синонимы, леммы, векторы) снова `eval pool` с его выдачей и доразметка
только новых документов: сравнивать варианты можно, когда покрытие оценками@10 у обоих близко к 1.

## Ограничения (важно)
- **Оценки `llm-silver`**: поставлены моделью (claude-sonnet-5-5) по названию и первым ~100 символам текста,
  вслепую к рангам и score (пул перемешан), но не человеком и не по полному тексту. Это предварительная разметка
  по протоколу, а не gold.
- **Человеческая проверка ещё не сделана**: `eval review` выдаёт 20 запросов (test) и их top-10 в
  `review/holdout.jsonl`; оценки вносятся в `review/human.tsv` (колонка grade), затем `eval agreement` считает
  согласие и Cohen's kappa. Пока этого нет, нельзя заявлять человеческий holdout.
- Разметчик один, межэкспертного согласия нет.
- Пул B0 строился по его же выдаче и выдачам перефразов (плюс 68 документов, найденных вручную), поэтому у B0 покрытие
  оценками 1.0 по построению, а recall — pooled (знаменатель — размеченные релевантные, не весь корпус).
- Русские запросы (`language=ru`) оцениваются по английским документам: это cross-lingual, ожидаемо 0 у лексического B0.
