# Продукт и требования

Редакция 2026-10-10. Rust Knowledge Search — рабочее название, не бренд. Поиск по устройству и развитию языка, а не по API библиотек.

## Семь обязательных критериев

| № | Требование пользователя | Решение | Проверяемый результат |
|---|---|---|---|
| 1 | Скрапить сайт | HTML Internals + HTML RFC, разрешённые discovery/pagination | Сохранённые HTML, manifest загрузок, отчёт о ≥5 000 уникальных тем |
| 2 | Получить JSON/CSV | Версионированный канонический JSONL, JSON-массив и табличный CSV | Читаемые экспорты; валидация, round-trip, rebuild индекса из JSON без сайта |
| 3 | Lucene или иной движок | Tantivy, Rust-библиотека в backend | Зафиксированная версия, схема, воспроизводимый build |
| 4 | Обратный индекс | Поля, словарь, postings с частотами/позициями | Сохранённый индекс; диагностический тест показывает term → документы/позиции |
| 5 | Приложение поиска, интерфейс свободный | Axum API + сайт; по уточнению пользователя CLI необязателен | Ввод запроса → ранжированные документы; проверка curl/OpenAPI/Swagger без frontend |
| 6 | Улучшения поиска | Опечатки, синонимы, настоящая лемматизация, векторы | Отдельные режимы и сравнения с baseline, тесты по каждому улучшению |
| 7 | Оценка качества | Offline graded relevance 0/1/2 + контрольная человеческая разметка | qrels, runs, nDCG@10/MRR@10/P@10 и отчёт; LLM-разметка помечена |

Упоминание «CERP» не трактуем как название известной метрики: фиксируем проверяемую оценку релевантности выдачи (SERP) по предложенной трёхбалльной шкале. Если у курса есть отдельная формула CERP, добавить её после получения определения.

## Что делает пользователь сайта

1. Вводит номер RFC, термин или естественный вопрос. Переключает lexical/vector/hybrid; видит активный режим и деградацию.
2. Фильтрует по источнику, периоду, исходной категории/тегам и машинной теме. Пустой фильтр не снимается без действия пользователя.
3. Открывает карточку RFC/дискуссии, совпавшие фрагменты и оригинал. Различает автора, дату материала и дату сбора.
4. Переходит по теме: например, async/concurrency, ownership/borrowing, traits/generics. Видит, откуда взялся тег и какие фрагменты его подтверждают.
5. Открывает локальный граф документа: настоящие ссылки, тематические узлы и предложенные похожие материалы. Выключает вычисленные связи.
6. Оценивает релевантность результата запросу по шкале 0/1/2; это отдельное действие, не автоматический вывод из клика.
7. Администратор наблюдает сбор/индексацию, приостанавливает источник, запускает повторный парсинг локального HTML и проверяет AI-теги.

## Границы

Интерфейс русский, основной корпус английский. Русскоязычный semantic search оцениваем отдельно; лемматизация не переводит запрос.

Обязательный учебный минимум: пункты 1–7 с уточнением интерфейса. Сайт — основной продукт, не поздняя оболочка обязательной CLI. Целевая веб-версия: поиск + классификация + граф явных ссылок/тегов. Семантические рёбра — расширение после оценки precision. RAG-ответы, дообучение Qwen, пользовательские аккаунты, отдельный поисковый CLI и A/B-тест — не условия первого релиза.

Нет сбора профилей, приватных разделов и комментариев GitHub. Ссылки за границы allowlist сохраняем как данные, но не посещаем автоматически. Статус stable/nightly не выводим из текста старого RFC. «Предложение принято» не значит «возможность стабилизирована».

Ранее выбранный минимум трактуем строго: 5 000 различных полных тем Internals, без зачёта дублей, якорей и chunks. Если пилот показывает невозможность такого корпуса в разрешённых условиях, остановить массовый сбор и согласовать критерий, а не менять счётчик молча.
