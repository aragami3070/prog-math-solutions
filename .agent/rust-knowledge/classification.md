# Темы, теги и Qwen

## Цель

Multi-label классификация документов по темам. Не генерация бесконечных похожих тегов и не определение того, что реально стабилизировано в Rust. Сначала исходные category/tags форума, затем отдельные машинные метки.

Начальная taxonomy v1, уточняемая на пилоте: `ownership-borrowing`, `lifetimes`, `traits-generics`, `async-concurrency`, `type-system`, `error-handling`, `macros`, `unsafe-memory`, `compiler`, `standard-library`, `cargo-tooling`, `performance`, `syntax-ergonomics`, `language-process`. Несколько меток допустимы; `unclassified` означает недостаток основания. У каждого ID — русское/английское имя, определение, включения/исключения и примеры. Версионировать конфиг, не жёстко вшивать в prompt.

## Модель и workflow

Кандидат: [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), опубликованный Qwen на Hugging Face. Не объявлять его оптимальным до замеров. Квантизация/runtime и размер модели зависят от доступной RAM/VRAM; скачивание весов — отдельный шаг реализации.

1. Создать ручной набор 100–200 документов, включая длинные и пограничные случаи, и простой baseline по source tags/ключевым словам.
2. Zero/few-shot классификация с закрытой taxonomy, JSON-контрактом и разрешённым отказом от решения. Fine-tuning не нужен для первого запуска.
3. Для короткого документа передавать title + основной текст; для длинного — разделы/посты по токен-бюджету, затем агрегировать метки по подтверждающим фрагментам. Не ограничиваться заголовком или первой страницей. Записывать долю реально обработанного текста.
4. Валидировать ID тегов, лимит 1–5 тем (или ни одной), существование section IDs и точность evidence quotes относительно входа. Невалидный JSON — ограниченный retry, затем review, а не сохранение произвольной строки.
5. Сохранить model ID + revision, tokenizer, runtime/quantization, prompt/taxonomy version, decoding params, content hash, coverage, результат и review state.
6. Человек может принять/отклонить/добавить метку. Ручное решение не затирается повторным запуском модели и хранится отдельным событием.

Выход: document ID/hash, topics[{topic_id, evidence_section_ids, evidence_quotes}], status (`proposed|reviewed|unclassified|failed`), provenance. Самооценка confidence от LLM не считается вероятностью или достаточным основанием автоматического принятия. Порог auto-accept возможен только после отдельной калибровки.

## Оценка и безопасность

Сравнить с baseline micro/macro F1, per-topic precision/recall, долю отказов, evidence-validity, покрытие текста, latency/стоимость. Разделить dev/test по документам и связанным темам, не по chunks. Итоговая оценка на ручном holdout; LLM-метки не выдать за gold.

Текст форума — недоверенные данные: инструкции внутри него не исполняются, инструменты и сеть модели не предоставляются. Генерация ограничена schema/allowlist. Prompt не содержит секретов. Нет автоматического обучения на всём корпусе или загрузки корпуса во внешний платный API.

Один и тот же document hash не прогонять повторно без смены pipeline. Классификацию выполнять фоном; страница и обычный поиск работают при выключенной модели.
